Michael Heilmann's Arcadia Visuals

This is the documentation for Michael Heilmann's Arcadia UI. Arcadia UI provides a user interface (windows, buttons, text fields, etc.) for Michael Heilmann's Arcadia Engine.

UI Basics: A user interface consists of a UI canvas node in which UI widgets are placed. The UI canvas node has a width and height, which may change, depending on the context in which the UI canvas is used. For example, a UI canvas might resize according to the application's window inner size. A UI canvas / its contained UI controls should react reasonably to these size changees.

Documentation

UI Interfaces

Engine.UI uses small runtime interfaces to describe widget capabilities. A concrete UI object implements only the interfaces whose operations it supports. Shared widget state such as geometry, focus flags, ownership, and signals should remain on concrete object types or common base objects; optional behavior belongs in these capability interfaces.

The interface source definitions live in individual .pdl files, one file per interface. The checked-in .c and .h files next to them are the PDLC-generated runtime bindings used by Engine.UI.

Interface dispatch remains exact: callers invoke the operation of the requested interface. The runtime adds ancestor interface implementation records for derived interfaces, but ancestor operation slots still need their own implementations. For this reason, operation-bearing UI interfaces are intentionally kept flat in the first UI foundation pass.

Interface Purpose Typical Implementers
Arcadia.Engine.UI.Renderable Renders an object into an active visuals enter pass. Labels, buttons, panels, sliders, scroll panels, dialogs.
Arcadia.Engine.UI.HitTestable Answers whether a UI-space point is inside the object's interactive region. Interactive controls and containers.
Arcadia.Engine.UI.Focusable Receives or releases keyboard/controller focus and reports focus state. Buttons, toggles, sliders, dropdowns, text fields, key binding rows.
Arcadia.Engine.UI.PointerInput Consumes mouse pointer and mouse button events. Buttons, toggles, sliders, dropdowns, scroll panels.
Arcadia.Engine.UI.KeyboardInput Consumes keyboard key events routed to the focused object. Focusable controls and key binding rows.
Arcadia.Engine.UI.Activatable Exposes a primary action independent of whether it was triggered by pointer, keyboard, or controller. Buttons, toggles, ordinary buttons used as tab headers, dropdown entries, segmented choice segments.
Arcadia.Engine.UI.ValueControl Gets and sets a control value using the current object-valued PDL interface contract. Toggles, sliders, dropdowns, segmented choices, text fields, key binding rows.
Arcadia.Engine.UI.Container Owns an ordered child list and defines composition/z-order. Canvas, panels, scroll panels, dialogs, composite controls.
Arcadia.Engine.UI.Scrollable Maintains a scroll offset and supports relative or absolute scrolling. Scroll panels and dropdown popup lists.

The first required options-screen controls should be built by combining these interfaces: button, toggle, slider, dropdown or segmented choice, ordinary buttons composed into a tab bar, scroll panel, key binding row, and warning label. Confirmation dialogs and preview panels reuse the same contracts.

Tab behavior in ADL

Use UI.Panel with layout.type: "UI.StackLayout" and an ordered children list of ordinary UI.Button definitions. Add the optional panel field behavior: "TabBar" to enable exclusive selection; if omitted, the panel retains normal layout-only semantics. selectedChild optionally names one direct child button to select initially; without it, no button starts selected. An unknown behavior, a selected child without tab behavior, a missing selected name, or a non-button child is invalid.

Tabs are selected through the existing button activation and the tab bar's selection signal. Focus does not itself select a tab. Left/Right change selection in horizontal bars; Up/Down do so in vertical bars. The bar owns tab headers only, not the application content. No UI.TabButton definition is required.

Composable dropdowns in ADL

A single-choice dropdown combines an ordinary UI.Button anchor, an UI.ScrollPanel popup, and ordinary UI.Button option children. Arcadia.Engine.UI.DropdownController connects their activation signals and owns committed selection, independent of the popup's transient keyboard highlight. Use unique option button names as stable selected values; the option text is its display label. No specialized UI.Dropdown or UI.DropdownOption schema is necessary.

Input bindings and warning/status messages

Use a normal UI.Panel containing UI.Label for the action name, current binding and status, and ordinary UI.Button controls for Edit and Reset. Arcadia.Engine.UI.BindingRowController connects the buttons to the shared InputBindingService. Action names and actual binding values belong to the runtime service, not to the ADL schema; unknown action IDs are rejected by the controller. The Controls gallery declares two such rows, Jump and Sprint, using the existing UI.Panel/UI.StackLayout/UI.Button/UI.Label types. There is no specialized KeyBindingRowNode or new reader schema.

Arcadia.Engine.UI.StatusLabel_set styles a normal label for information, success, warning or error. Status text MUST provide a non-color cue such as Conflict: or Invalid:; the label colors are supplementary. A null status hides the label text. Captures are modal: click Edit, press a new key or mouse button, Escape to cancel, and Reset for the application's default binding. Bindings shown in the example are session-only; persistence belongs to the application.

UI.ScrollPanel requires left, bottom, width, height, contentWidth, contentHeight and a children array. Content dimensions must not be smaller than the viewport. Unknown or incorrectly typed fields are rejected. The popup is installed through the canvas overlay API, not as a regular canvas child: this provides topmost rendering, Escape/outside-click dismissal, wheel scrolling, viewport-constrained positioning and focus restoration. Up/Down navigate enabled options; Enter/Space commits. The controller's selection signal fires only on value changes.
