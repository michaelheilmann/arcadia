# Arcadia Sanitizer

## Documentation

The sanitizer has a dedicated documentation site generated by the Arcadia
Template Engine. Its source lives in `Tools/Sanitizer/Documentation`, and
its output is `.Website/Arcadia/Sanitizer/index.html`.

Build it with:

```sh
cmake --build build --target Arcadia.Sanitizer.BuildDocs
```

The documentation separates the introduction, concepts, specification, and
native module interface. This README is a short developer reference.

Native C CLI and testable library, built using Arcadia's own `FileSystem`,
`FilePath`, `DirectoryIterator`, `FileHandle`, `ByteArrayBuilder`, and Testing
modules. No PowerShell or Python runtime is needed.

## Build

From a configured Arcadia build tree:

```sh
cmake --build build --target Arcadia.Sanitizer.Tool
cmake --build build --target Arcadia.Sanitizer.Tests
ctest --test-dir build -R Sanitizer --output-on-failure
```

Run the resulting `Arcadia.Sanitizer.Tool` executable (its location depends on
the CMake generator/configuration) with one of the following commands:

```sh
Arcadia.Sanitizer.Tool --check /path/to/file-or-directory
Arcadia.Sanitizer.Tool --fix   /path/to/file-or-directory
```

With no path argument, the working directory is used.

- Exit 0: clean (or successfully fixed).
- Exit 1: formatting differences found in `--check` mode.
- Exit 2: invalid arguments or an I/O/runtime failure.
- Reports `path:line: whitespace differs` or `path:line: fixed whitespace`.
- CRLF and bare CR become LF; trailing spaces and tabs are removed. Internal
  spaces and tabs, byte encoding, BOMs, and the presence or absence of the
  final newline are preserved. Clean files are not written.
- Recursive scans include `.txt`, `.c`, `.h`, `.i`, `.tl`, `.te`, `.pdl`,
  `.adl`, `.ddl`, `.md`, `.cmake`, `.c.g`, and `.h.g`.
- Excludes `.git`, `.vs`, `.venv`, `.Dependencies`, `build`, `.build`,
  `CMakeFiles`, `node_modules`, `__pycache__`; explicitly provided regular
  files are processed even with other extensions.
- Files containing a NUL byte are reported as skipped binary data.
- Symbolic links and Windows reparse points are not traversed or modified;
  an explicitly selected link root causes exit code 2.

`--fix` uses `Arcadia_FileSystem_setFileContents`, which writes the file in
place rather than using a transactional replace. Check your Git diff before
committing; consider a backup for important non-versioned files. This tool is
not a syntax checker, C formatter, or PDL/ADL canonical rewriter.

Full-repository `--check` is not yet an unconditional CI gate because existing
formatting debt must be normalized separately. The CTest regression tests are
registered in the regular Arcadia test discovery system.
