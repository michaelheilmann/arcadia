# PDLC Folder Guide

## Scope

- `PDLC` contains the current compiler library target `${MyProjectName}.PDLC` for Arcadia PDL, the Arcadia Program Definition Language.
- The library owns Arcadia PDL scanning, parsing, AST nodes, symbols, compiler phases, diagnostics, compilation task orchestration, and C backend writers.
- Command-line behavior lives in `PDLC.CLI`; keep reusable compiler behavior in this library rather than in the CLI.

## Language Specification

- Keep structural PDL declarations backend-independent. Inheritance implies the inherited base portion; `_parent` fields and C dispatch structs are synthesized by the C backend, not written into PDL models. Express fields, callable semantics, types, constants, nested declarations, and ownership in PDL terms. Do not replace missing language features with quoted C declaration templates or explicit C function-pointer slots. Native target/header annotations are interoperability metadata; ABI/layout comparisons belong in backend tests.
- The Arcadia PDL specification is `Documentation/Specifications/Program Definition Language/index.html.te`.
- Arcadia PDL intentionally does not imply a particular abstraction level, storage duration, or implementation strategy; it simply defines a program.
- Treat `Scanner.c`, `Parser.c`, AST node types, semantic phases, backend behavior, tests, and checked-in `.pdl` inputs as the primary executable evidence for current behavior.
- When changing accepted Arcadia PDL syntax, lexical words, instruction forms, primitive semantics, or observable diagnostics, update the PDL specification in the same change when practical.
- If implementation and specification disagree, prefer the implementation for fixing immediate behavior, but either update the specification or leave an explicit follow-up note in the change summary.

## Hand-Written C Invariant

- `PDLC` must remain hand-written C: no production PDL port, generated headers/bodies, self-hosting or compiler/CLI production regeneration entries. Follow the [root native-C invariant](../AGENTS.md#start-here) for the full protected set, test/import exceptions and explicit-approval requirement.
- PDL fixtures and generated-code tests under `PDLC/Tests` remain essential compiler coverage, not production regeneration modules.
- The earlier OperandNode/StatementNode self-generation and interrupted VariableOperandNode/RegisterOperandNode work have been removed. All four classes use their original hand-written C implementations/headers again; retain the independent compiler fixes and regression tests. Do not reintroduce their production PDL models or generated bodies.

## Build Wiring

- PDLC has no production PDL module or self-generation entry in Modules.pdl. Its production sources are native C; constructor contracts, offsets, managed-reference lifetime and regression coverage remain unchanged. Public consumers must not inherit implementation-private compile definitions.
- The root module file adds `Library` and `Tests`; the library target is declared in `Library/CMakeLists.txt` with the repository `BeginProduct` macros.
- Source and header files are registered explicitly with `OnSourceFile` and `OnHeaderFile`; update `Library/CMakeLists.txt` when adding, moving, or deleting compiler source files.
- `OnSourceFile` centrally recognizes `.c.g` as C translation units. Production targets register committed PDLC output with normal `OnSourceFile` calls; do not repeat low-level LANGUAGE properties or classify old `.c` implementations as headers. Temporary native equivalence references belong under the active migration's test sources and are retired after the production gates pass.
- Generated configuration headers come from `Configure.h.i` via `OnConfigurationFile`; include the generated `Configure.h` through normal target include paths.

## Compiler Structure

- SceneManager is PDL-owned/generated in the core Engine module (SceneManager.pdl/SceneManager.c.g), with nullable Scene references and nonvirtual transition methods; Signal remains a native opaque dependency. Its PDL model owns publication/branching and keeps the old scene in a managed local until notification completes. SceneManagerRuntime.c preserves required Engine validation/Signal creation, literal pointer comparison and Signal's caller-owned argument frame; generic equality/identity operations are overridable and must not replace that comparison. Nodes/SceneManager.c retains native/generated-verified transition, reentrancy, exception, ABI and GC checks after temporary providers are retired. No compiler feature was added for this port.

- Context.scope contains top-level type/procedure declarations; Context.moduleScope contains only module symbols and is never a lexical parent. Module and type names may be identical (Arcadia.Engine is both). EnterPhase checks duplicates independently, restores built-ins on repeated runs and creates each module's declaration scope over Context.scope. Backend discovery visits both domains; dependencies follow symbol ownership, not name matching. Do not reintroduce a native C-name alias to work around module/type name equality.
- Variable declaration metadata includes `isReference`, `isReadOnly`, `isOutput`, ownership, value-record fields, and optional integer initializers. AST `type`/resolved symbol `type` is null only for a structural record with its own field list; these are value fields, not lexically nested type definitions. Visit both AST and resolved record-field lists for GC.
- `TypeResolutionPhase_resolveParameter` is the shared data-declaration resolver for parameters, class fields, and record fields. It resolves fully qualified referent types, copies semantic qualifiers, rejects duplicate record fields, and checks Integer32 constant ranges with source diagnostics.
- `method nonvirtual` records callable semantics in AST and symbols. The C backend derives the absence of a dispatch slot and uses a direct wrapper; overriding or hiding inherited nonvirtual members is rejected. Override checks include reference/read-only/output modes as well as referent types.
- `Scanner.c`, `Keywords.c`, and `WordType.h` define the lexical word stream and reserved words.
- `Parser.c` defines the accepted syntax and builds `AST/*` nodes.
- `EnterPhase`, `MemberEnterPhase`, and `TypeResolutionPhase` build and complete symbols; keep symbol invariants local to the relevant phase where possible.
- `Backend*` code writes generated C and headers. Preserve generated-file header strings when changing licensing or public generated output.
- Diagnostics are ordinary compiler output. Prefer adding precise diagnostics over raising generic status values when the caller can recover and report useful source information.

## Native Definitions And Native Names

- Native classes accept an optional C header mapping: `native "Path/To/Header.h" class Qualified.Type ...`. The string is stored in `ClassDefinitionNode.nativeHeaderPath` and visited by the GC. It is distinct from callable native target names; it changes neither the runtime type name nor the derived C identifier. The parser validates a nonempty relative forward-slash path without empty/dot/dot-dot components or include-delimiter/control characters; C include search paths resolve it, so the header need not be present in the PDL module tree.
- Generated classes may use `class "Path/To/Header.h" Qualified.Type ...` (optionally abstract) to preserve established C paths. Reuse the same visited mapping metadata without changing native ownership flags: the header is module-owned and its source is the same path with `.h` replaced by `.c.g`. Generated mappings require `.h`, preserve path-derived guards, and participate in duplicate/opaque/aggregate output protection. MappedClassPath tests unsafe paths; the real ThinResources implementations exercise mapped output ownership end to end.
- Generated enums likewise accept `enumeration "Path/To/Header.h" Qualified.Type { ... }`. The existing visited nativeHeaderPath metadata stores the mapping without changing isNative: the backend owns the mapped .h and adjacent ordinary .c (not .c.g). Source includes and guards follow the mapped header path; runtime/C names and cross-module master-header dependencies do not change. Safe-relative-path/.h validation and generated/opaque/aggregate collisions are checked before writes. Native enums keep their existing prefix mapping syntax and external ownership; native-implementation classes may still publish their explicitly shared native enums. Backend's Test.Color and CrossModules' Example.A.Flavor exercise fresh mapped output, transport, guards and foreign master includes. Semantic negatives cover unsafe paths, extension, aggregate, duplicate and opaque/native collisions and double mappings.
- `Backend/ClassSymbolInfo.c` applies the mapping centrally. Both generated source dependencies and header superclass dependencies use the mapped metadata. An explicitly mapped opaque native header has no absolute generated-output path: C include search roots resolve it. Plain native classes without a mapping preserve their qualified-name-derived header paths. Native implementations have no source output path; declaration ownership is explicit as described below.
- `native implementation "Path/To/Header.h" class ...` means PDL owns declarations while the executable implementation is supplied natively. `isNativeImplementation` implies `isNative`; both AST and symbols carry it. Unlike an opaque native class, it has a module-relative header output path. Normal CLI/CompilationTask generation emits its real `.h` but no `.c.g`/factory. Header guards follow the mapped file path. Native enums mapped to the same header are emitted as top-level declarations in that file; this is not lexical nesting.
- Before writing native-implementation headers, the C backend rejects duplicate output owners, module-aggregate replacement, non-`.h` paths, and loss of opaque native class definitions sharing a generated header. Header emission is validated before output writes. Ordinary native classes and externally supplied enum headers remain untouched.
- Top-level native enums accept the same optional header mapping: `native "Path/To/Header.h" enumeration Qualified.Type { ... }`. `EnumerationDefinitionNode.isNative/nativeHeaderPath` and `EnumerationSymbol.isNative` preserve native ownership. EnumerationSymbolInfo uses the mapped header and no output path; the backend skips enum file emission. Executable transport uses the existing EnumerationValue and requires the native provider's conventional `_CType_getType(thread)` runtime descriptor. Transported native C enum ABIs must fit Integer32 storage; generated assertions and boxing/unboxing numeric round-trip checks prevent silent narrowing or signedness changes. Keep native enum files/macros under native ownership.
- A qualified type name may contain another type's name as a prefix without lexical nesting. The Backend fixture Test.NativeDeclared.Kind is a top-level native enum sharing a header with Test.NativeDeclared, not a nested class declaration. Do not reintroduce nested-definition AST/symbol machinery just to reproduce this naming convention.
- `native` is an optional clause of a procedure, constructor, or method definition: `procedure native "print" print (...)`, `procedure native "nativePrint" MyNativeProcedure (...)`. It takes a string literal naming the native target.
- `nativeName` on `ProcedureDefinitionNode`, `MethodDefinitionNode`, and `ConstructorDefinitionNode` is **optional and source-derived**: it is populated only when the compilation unit carries the clause, and is `NULL` otherwise. `NULL` means "no clause was written", **not** "this member is not native".
- No symbol has a `nativeName` field of its own. Resolve native targets through `Arcadia_PDLC_Symbols_getNativeTarget`, which handles source annotations and the `nativeTargets` registry. Register a built-in native member with `Arcadia_PDLC_Symbols_setNativeTarget`; it need not have an AST or completer. Do not branch on AST presence in a writer.
- Treat "is this member native?" and "what is its native target?" as two separate facts. A native member has two provenances: annotation-derived from PDL source, and registry-derived from a built-in type. Resolve both at one point and expose the result through a single accessor; do not let a backend writer branch on AST presence or on provenance.
- A native target name is a **verbatim C identifier**. Never pass it through `Arcadia_PDLC_Backend_Implementation_computeCxxName`, which replaces `.` with `_` to derive an implementation name from a fully qualified PDL name.
- A member of a native class may bind to its conventional public C name (for example `Arcadia_Engine_Visuals_Resource_load`): that owner has no generated public wrapper to collide with. Generated-owner public-entry collisions and private `_impl` adapter collisions remain errors. Native resource members call the existing C wrappers; this does not model or change their C dispatch-slot layouts or nonvirtual status.
- `TypeResolutionPhase` completes a symbol only when `symbol->completer` is non-null, so a native member whose types are supplied from C rather than from AST type names, and which has no completer, is skipped safely and needs no phase changes.
- Member lookup is by **declared, unqualified name** in the scope of the class type that declares the member. Top-level procedures may have qualified declared names, like types; qualified call/invoke targets resolve those exact names rather than performing method lookup.

## C Backend

- `Backend/CallableWriter.c` shares executable-body generation between procedures, methods, and constructors; class and procedure writers delegate to it. The backend validates all callable bodies before writing files.
- Built-in runtime classes include `Arcadia.Object` and `Arcadia.String`. `Symbols/Symbols.c` owns the built-in registry. File emission must skip every type recognized by `SymbolInfo_isBuiltIn`; do not special-case only Object, since built-ins have no module metadata or generated files.
- `Arcadia.Size` is a built-in primitive mapping to `Arcadia_SizeValue`/`size_t`, with the distinct runtime Size value tag. Keep it distinct from Natural64 even on x64. Its ABI, boxing, conversions, and helper collection are covered by the compiled Backend tests, including maximum-size values, factories, fields, native calls, forced GC, and rejection of a Natural64-tagged argument.
- Replacing hand-written headers is the first priority. Public procedure/method entry points and dispatch slots use typed C parameters/results; procedures have no receiver, and methods take a declaring-class receiver after `thread`. Constructors are private `void` initialization operations with runtime value-stack callbacks; concrete factories take typed constructor parameters. See the PDL specification's `6. Execution Model.i` for the full ABI and member/parameter escaping rules, and `AGENTS/CxxSourceCodeStyle.md` for formatting.
- Public native-target function declarations follow the same multiline layout and declared parameter naming as other public functions. `nativeSignature` must use `typedParameters` in header context; its compact positional-parameter form is only for body-local native-target `extern` declarations, not public headers. Dispatch function-pointer members retain their explicit single-line exception.
- An explicit first-statement superclass construction may invoke a native parent's runtime constructor using its declared signature. This initializes self through the real native type operations and then publishes the generated derived type; it does not synthesize a native allocator. NativeParentAllocation retains the direct-native-allocation diagnostic. Resource's declaration-only constructor supports the four thin derived resources, including ProgramResource, without migrating Resource.
- Abstract typed C wrappers can forward readonly external byte inputs and scalar output pointers directly to native overrides. Do not box their addresses or trace their storage. Readonly object arguments still receive normal GC roots. Executable PDL calls needing external-reference/record value transport remain diagnosed in callArguments/callableBody; AbstractReferenceValue covers that distinction.
- An override must preserve the inherited dispatch slot's exact function type. Use a forwarding thunk when the implementation takes a derived receiver; do not assign incompatible function pointers by casting them.
- Internal PDL registers and mutable parameters remain value-stack slots independently of the typed C interface. Root incoming receivers, object/interface parameters, and general-value parameters before any operation that can collect, including enum/type metadata resolution. Trace object/interface and `Arcadia.Value` fields in visit callbacks, and restore entry stack depth on failure.
- Class method wrappers validate non-null managed class/interface arguments before dispatch, not just inside generated bodies: raw native overrides have no generated body to enforce those checks. Establish all roots before descriptor lookup. Keep nullable arguments and direct external-reference/output-pointer forwarding; interface operation wrappers remain stackless and unchanged. Backend's AbstractNativeBase.accept regression installs a raw native slot to check class/interface mismatch rejection before callback entry above 255 slots; removing wrapper validation makes that test fail.
- Generated runtime constructor callbacks normalize legacy Integer32 arguments for enum parameters, including supported native enums, to the declared enum type. This C interoperability adaptation does not loosen PDL enum typing: allocation converts through exact-type checks, and explicit superclass forwarding checks enum identity before entering the parent callback. Backend tests cover matching numeric values from different enum types and raw integers at both PDL boundaries, native enum fields/factories/methods/native calls and results, negative/minimum/maximum values, unsigned range rejection, GC and wide-stack cleanup. Conversion helpers and native ABI assertions are emitted only for enum types actually transported.
- Nullable class/interface parameters, fields, and results use PDL void for absence: box C `NULL` as `Arcadia_Value_makeVoidValue(Arcadia_VoidValue_Void)` and unbox void to `NULL`. Never create an object-reference value with a null pointer. Non-null references remain runtime-type checked; receivers for method dispatch and field access remain non-null. See the specification for the distinct void receiver used for allocation.
- Class/procedure headers are generated directly as `.h`; their sources remain experimental `.c.g`. Interface/enumeration headers and sources use `.h`/`.c`. There is no header-copying, publishing, or installation step.
- UI's Activatable, HitTestable, Focusable, Scrollable, Renderable and KeyboardInput definitions are verified ordinary interface output. Existing PDL models and writer output were already present; complete adoption required baseline/CLI byte-equivalence and runtime/ABI coverage, not .c.g conversion or native-body duplication. Their wrappers preserve Arcadia_InterfaceCall's stackless C contract and NotImplemented status for absent interfaces/slots; caller-owned managed roots remain required. Do not silently introduce value-stack frames into these callbacks. UI EventBases carries the ABI, native-probe and real-widget tests without another CTest target.
- Procedure output paths follow their declared names: M.N.p emits M/N/p.h and M/N/p.c.g beneath Library/Sources. Its C entry point is M_N_p, without prefixing the enclosing module a second time. Use qualified procedure names for namespaced production output; existing short-name procedures retain their legacy flat paths and module-prefixed C names. Native target identifiers remain verbatim. Qualified targets resolve in the compilation's global scope when absent from the caller's module; unqualified calls retain current-module lookup. Procedures participate in duplicate-header ownership and module-aggregate protection before output writes.
- Opaque native classes retain their hand-written definitions. Do not replace a complete hand-written header with output from an incomplete placeholder; use a plain native declaration until its PDL description can represent the existing layout and API. Window is an example.
- Once a native class model is complete and verified, opt into real declaration generation with `native implementation`; keeping it as plain `native` will intentionally skip regeneration even if a test-only model preview passes.

### Dependency Collection

- Shared native collection declarations belong to the Arcadia.Collections module under Runtime/Collections, not Engine. NativeTypes.pdl contains eight imports, including ImmutableList for Media's declaration-only VertexDescriptor model, without changing their runtime/C names or implementations. The module emits no collection headers or bodies; its defining master is Arcadia/Collections/Include.h. Root regeneration and ResourceModels staging include Collections. ResourceModels checks all eight native owners and absence of output paths after GC, keeping Media's collection use independent of Engine.
- ADL's Arcadia.ADL module owns eleven opaque native imports: Definition/Definitions, two pixel-fill definitions and seven audials/visuals factory argument types. They emit no native headers/bodies. Definition's constructor/link metadata allows its five generated descendants (ColorDefinition, WhiteNoiseDefinition, ConstantDefinition, SineWaveDefinition, SawtoothWaveDefinition) to use the actual native superclass constructor and inherited slot; the handwritten Definition/Definitions headers, storage and visitors remain native. Their native header mappings select local Definition.h/Definitions.h for same-module dependencies; foreign dependencies still use Arcadia/ADL/Include.h. ADL also owns five generated enums (TextureFilter, TextureAddressMode, MaterialType, AmbientColorSource, BlendFunction), with the independent four-way TextureVertex asset contract retained. Its private switch is ARCADIA_ADL_PRIVATE, with EXPORT unchanged. ResourceModels checks all eleven native owners/absent output paths and all five generated class output owners after GC, alongside the descriptor and Engine factory ownership checks. Ordinary ADL Definitions/ClassModels.c retains per-class ABI/constructor/tag/dispatch/GC/error regressions after temporary comparison providers are retired. Media DSP is not migrated by these ADL configuration-object ports.

- **Cross-module includes must use the defining module's master include file.** If module B uses a type defined in A, emit A's `Include.h`, never A's per-type header and never a foreign `_PRIVATE` define. `SymbolInfo_getDependencyHeaderFilePath` selects by actual module ownership, not a type-name prefix. Same-module dependencies may use individual/mapped headers; built-ins come from the runtime aggregate. Forward declarations may avoid an include when no complete definition is needed.
- Both CallableWriter and InterfaceSymbolWriter use this selection. Interface headers collect enum signature dependencies; interface sources collect extended-interface dependencies. Deduplicate after resolving to the selected path, since multiple symbols from A share one master header. Master headers must expose their module's public declarations while containing their private-header switch internally.
- Emit only the dependencies required by each generated file, deduplicated and sorted by C name; a source includes its own header first after the runtime include.
- Deduplicate emitted include paths as well as symbol dependencies: multiple native classes can map to the same public aggregate header (for example the Media and Math dependencies of visuals resources).
- Headers need complete definitions for embedded parents and enum-valued fields or callable parameters/results. Class pointer fields and callable parameters/results need forward declarations, except when the type is already supplied by an included header. Runtime types come from the runtime aggregate include.
- Source generation buffers the body and records dependencies through emitted C names (`cname`), including conversions, `_getType` references, construction, dispatch, and native calls. Emit the collected include preamble before appending the buffered content.
- Required native method adapters are collected on demand and emitted ahead of their callers. Do not restore compilation-wide adapter or forward-declaration emission.
- Conversion helpers (`pdlAs*`) are collected while emitting bodies and native adapters. Emit only used conversions; include direct Boolean conversions for conditional branches in that collection.
- `entries()` deliberately spans the compilation for symbol lookup and dynamic method/field dispatch. Pruning includes must not narrow that lookup: every candidate branch actually emitted still needs its declaring types, even when they belong to other modules.
- A field access whose receiver is the declared `self` resolves its field owner in the declaring class hierarchy; fields cannot shadow inherited members. Do not emit unrelated same-named-field branches for self, which can introduce reverse module dependencies (for example Engine.Event.timestamp to UI.Event). Dynamic receiver accesses retain the global candidate search. Backend's intentionally unlinked UnlinkedSized fixture guards against spurious self-field link dependencies.

### Header Compatibility And Regeneration

- UI.DefinitionFactory.pdl owns populateContainerFromDefinition's ordered traversal as a qualified generated procedure, exported through DefinitionFactory.h/UI's aggregate without changing its C signature. Capture the native ADL child list and its count once; read each current list element in order, resolve/create/add immediately, and retain partial additions on errors. Do not snapshot the list, pre-resolve all references, roll back, deduplicate repeated references, or skip native widget factories. DefinitionFactory.c keeps the original eight-way createNodeFromDefinition dispatch plus small collection/reference/Container boundaries. Collection and ADL dependencies stay with their defining modules' master headers. UI EventBases/Populate.c covers order/aliasing, captured count with list growth, replacement of later entries, empty-source unused targets, nested real StackPanel creation, callback/ref/type/factory errors and >255-slot cleanup. Generated lifetime cases collect with otherwise unrooted source/target/child and a captured list detached from its source; success/failure must release those roots afterward. This is setup traversal, not a per-pixel/sample migration.
- Native PixelBuffer width/height resizing copies the retained same-format pixel span row by row, excluding line padding and preserving the constructor's initialized new area. Keep the receiver and temporary rooted with exception-safe stack cleanup. Do not restore per-pixel getPixelRGBA/setPixelRGBA copying: those call generated format queries repeatedly and caused first-use texture stalls after migration. PixelBuffer/Formats.c covers all six color formats, padded growth/shrink/no-op behavior, default black/opaque new pixels, alpha retention and a larger resize. Its guarded fill checks also cover native BGRA fill's corrected single pointer advance; the old double offset wrote out of bounds.
- Media.PixelFormat.pdl owns the nine unchanged enum values and the qualified getNumberOfBytes/getNumberOfComponents procedures. ABGR now reports four components (the maintainer-requested correction to the native query's old three); all formats use one byte per component. Unknown enum values still raise ArgumentValueInvalid. PixelFormatRuntime.c retains only checked Natural64-to-Size conversion and the error boundary. The public query signatures/names remain exported by Media's aggregate, with declarations in PixelFormat/getNumberOfBytes.h and getNumberOfComponents.h; native PixelBuffer.c includes its query dependency explicitly. PixelBuffer storage and transcoding remain native. Formats.c in the existing PixelBuffer suite covers enum ABI/metadata/GC, all nine query results, invalid values and deep-stack cleanup, plus padded clone/conversion consumers across all six color formats. These conversions exposed native setPixelFormat allocating source-sized storage for a larger target; allocation now uses target bytes per pixel.
- Media.SampleFormat.pdl owns ordinary SampleFormat.h/.c and the generated qualified SampleFormat.getNumberOfBytes procedure (.h/.c.g). Preserve Integer16=0/Integer8=1/Natural16=2/Natural8=3/Real32=4 and the legacy rejection of Real32 by the byte query. PDL owns the enum branching; SampleFormatRuntime.c only converts the chosen Natural64 byte count to Size and preserves ArgumentValueInvalid for unsupported formats. The query keeps its public C signature/name and is exported through Media's aggregate; its declaration now lives in SampleFormat/getNumberOfBytes.h rather than the enum's private header. Native SampleBuffer.c explicitly includes the new procedure header; sample storage/conversion/clone implementations remain native. Existing SampleBuffer/Formats.c retains enum ABI/metadata/GC, bytes/errors/deep-stack and native consumer regression coverage after temporary providers are retired.

- Before migrating old output, compare every `xxx.h.g` directly with its corresponding hand-written `xxx.h`. For direct `.h` generation, review the diff against the previous hand-written/Git version. Check fields and their order, base members, dispatch slots and their order/types, factory signatures, other public declarations, include paths, and guards.
- Compile existing hand-written implementations and their consumers against the actual replacement headers. Generated-source compilation alone does not establish compatibility with the hand-written implementation. Retaining hand-written `.c` implementations while using generated `.h` files is the intended header-first workflow.
- A test-only `_PDLModel` fragment proves layout/signature compatibility, not normal CLI output generation. Close a declaration migration only after the regular CLI configuration regenerates the actual intended files, the real native implementations/consumers compile against them, and a second run is byte-identical. Check the declaration's output ownership (`class`, plain `native`, or `native implementation`) when an expected file is skipped.
- After class/header changes, build the relevant consumers; Engine migrations have been checked with `Arcadia.Media`, `Arcadia.Engine`, and `Arcadia.Engine.UI`. Run compiled generated-code tests separately, then regenerate a second time to verify byte-identical output. Use the external build trees and regeneration/quoting instructions in root `AGENTS.md` and `PDLC.CLI/AGENTS.md`.
- Review old `.g` files when a declaration becomes native: skipped native output can leave stale snapshots behind. Remove only artifacts confirmed to be obsolete, after checking their consumers and any local changes.

### Current Limitations And Follow-Ups

- Abstract classes and explicit `method abstract` declarations are supported. Abstract methods require an abstract declaring class and no body/native target/nonvirtual modifier. Concrete non-native classes must implement or inherit all abstract obligations, including re-abstracted methods. Native providers remain responsible for implementations supplied externally. Missing ordinary bodies keep empty-body behavior.
- The C backend emits abstract method declarations/slots/wrappers but no private implementation. Abstract and re-abstracted slots are initialized to NULL; all generated virtual wrappers raise OperationInvalid for a null slot and unwind their frame. Concrete overrides use the inherited slot's exact receiver/function type.
- Native resource models describe nonvirtual operations, semantic readonly/reference/output annotations, ownership, value-record fields, Integer32 constants, and associated top-level native enums. Their `native implementation` declarations regenerate real C headers while retaining native implementation bodies. The C executable backend diagnoses external-reference/record value transport and ownership-qualified non-native storage until those runtime operations are implemented; it never treats external addresses as object references or integers.
- External-reference value transport is deliberately deferred until generated executable bodies need it; it is not a prerequisite for regenerating typed headers or compiling retained native C implementations. The maintainer's chosen approach is native class objects wrapping the storage, for example `Arcadia_ByteArray`/`Arcadia_ImmutableByteArray`, rather than adding raw `void*` storage to `Arcadia.Value`. Keep the current diagnostic until that object-based boundary is implemented; do not substitute integer encodings or treat target addresses as managed object references. See the implementation-plan note in specification section 6.
- The C backend maps declaration-level scalar/untyped references to typed/void pointers, readonly object views to const-qualified referents, value-record fields to embedded anonymous structs, and constants to prefixed macros. `_PDLModel` fragments are verification-only and do not register runtime types; they are distinct from normal `native implementation` generation, which writes the real mapped declaration headers.
- The C backend creates missing output namespace directories for classes, procedures, interfaces, and enumerations. Modules still require a `Library/Sources` input directory. Missing input directories and output-directory/file failures produce path-specific `FileSystemDiagnostic` errors while preserving failure status.
- Generated source `Arcadia_defineObjectType` calls use `u8` type-name literals and three lines: the type name/C type, the parent name/C type, and the operations pointer, with continuation arguments aligned beneath the first argument.
- Backend tests compile `.c.g`; production migrations require per-class constructor/method/dispatch, GC/ownership, and error equivalence plus compiled consumer/runtime tests. Core Engine Event, Node, NodeFactory, Visuals.Icon and Visuals.CanvasEvent compile their `.c.g` after paired native/generated and production-linked tests passed. Event/CanvasEvent coverage includes timestamp state and real native descendant constructor chains. Node's setters are abstract: native Node has no context fields or default implementation. Do not replace those declarations with ordinary empty bodies, which would install no-op callbacks instead of preserving unbound base slots. Other classes retain their native implementations until their own checks pass.
- Follow the ordered implementation-migration workflow in `Engine/AGENTS.md`: paired tests precede the switch and a separate Production variant resolves the switched library. Once gates pass, retire comparison targets/providers and retain production assertions as a named case in a coherent linked-library suite, keeping the original safeExecute boundary. Completed migrations must not accumulate permanent triples or per-class executables. Report verified tests/builds; an application build is not an interactive smoke run.
- The concrete canvas payload events are migrated; CanvasPayloadEvents in Engine's WindowCanvasEvents suite checks real factories/constructors and preserves offset, distinct-tag and distinct-axis regressions.
- MouseButtonEvent/MousePointerEvent and KeyboardKeyEvent are covered by the named cases in Engine's InputEvents suite, including typed/legacy callbacks, enum identity, errors, wide stacks and managed native descendants. KeyboardKey remains a native macro-based enum.
- ApplicationEvent/ApplicationQuitRequestedEvent and WindowClosedEvent/WindowPositionChangedEvent/WindowSizeChangedEvent compile generated production implementations with ApplicationWindowEvents regression coverage. Their constructors preserve the corrected nullable-window behavior; retain null-window and event-only managed-window retention assertions.
- Core Backend/BackendContext, Audials/Visuals Backend and DisplayMode are covered by BackendBases in Engine's Backends suite. Native consumers exercise all eight operations, typed returns, errors/lifetime and production receiver/unbound-slot safety.
- Audials.BackendContext is covered by its case in Backends. Preserve the no-op setMasterVolume body, abstract creation methods and inherited abstract update. SampleBuffer/audials Resource remain native imports; provider/sound-source bases are now generated. Tests cover Real64 edge values, typed/null returns, native dispatch, errors, lifetime and roots.
- Audials.Node/Visuals.Node have the RenderNodes case in Engine's Nodes suite; their render slots remain abstract. UI's generated event hierarchy (including position/size leaves) retains EventBases with native widget sources. UI.Node is generated; WidgetNode and EnterPassNode remain native imports. The UI field models required the declared-self lookup fix above.

## Type Names

- `abstract class` declares a non-instantiable class; `abstract native class` is also accepted. `isAbstract` is carried by class and method ASTs/symbols. Class abstractness is not inherited. Keep abstract class constructor implementations for superclass initialization, but emit no `_create` entry point. A PDL construction naming an abstract class is valid only for immediate-superclass initialization as the first constructor statement with receiver `self`. Explicit abstract methods are inherited obligations, not empty ordinary bodies.

- Type names are always fully qualified and there is no relative resolution, so a `.pdl` source must spell `Arcadia.Natural64` and not `Natural64`. Member names remain unqualified; procedure declarations may use qualified identifiers and are called by those exact identifiers.
- Type resolution is performed by the type resolution phase and reports `SymbolIsNotDefinedDiagnostic` for an unresolved type name; it is not deferred to the backend.
- Because resolution is enforced, a latent unqualified type name in a `.pdl` input becomes a hard error. When a new error appears while regenerating `.pdl` inputs, check for a mistyped or unqualified type name before assuming a compiler regression.

## Instruction Operands

- Named operands may reference fully qualified declared enum constants. Parser.onExpression reuses onIdentifier/Names_toTypeName and retains the joined name in VariableOperandNode; both the parser's temporary identifier/list snapshots and the operand's stored name remain rooted. CallableWriter resolves enum members only after local/parameter lookup, emits typed generated/native enum boxing, and collects the enum's actual defining-module dependency. Constants are read-only, not implicit locals or writable targets. Missing members remain diagnostics. Do not substitute raw numeric enum values or introduce module/type aliases.
- For isEqualTo/isNotEqualTo, operation retains an existing scalar callback; only a missing callback on an enum left operand falls back to exact descriptor/payload comparison. Guard the right tag before calling generic runtime equality. Do not change object dispatch or invent enum arithmetic/order support. Backend covers constants in registers/construction/returns, wrong enum identity, native constants including INT32_MAX and unsigned macro constants, collection between uses and deep-stack cleanup. CrossModules returns a foreign constant as Arcadia.Value so the generated source (not its signature) must collect the foreign master include. Semantic negatives cover unknown members and constant targets.

- An instruction does not use a comma. The operands of an instruction are adjacent, as the grammar in `Documentation/Specifications/Program Definition Language/4. Syntactical Translation.i` shows; `binaryInstruction : binaryOperator operand operand operand` is the model.
- `invokeInstruction : 'invoke' operand identifier operand operand*` and `constructInstruction : 'construct' operand identifier operand operand*` do not parenthesize the argument list. A qualified invoke identifier denotes a procedure; method names remain unqualified. The constructor class identifier is fully qualified. `InvokeInstructionNode` stores the 1st operand as its `target`, exactly like `ConstructInstructionNode`; a new consumer must expect that field.
- `callInstruction : 'call' operand identifier operand*` is the explicit procedure-only invocation form and permits zero arguments, including qualified targets. It is represented by an `InvokeInstructionNode` with `procedureOnly` set. Unqualified invoke first looks for a procedure in the current module; otherwise its first argument is the method receiver. Both forms store the return value in their target.
- Commas are still used by declarations: parameter lists, `variable` declarations, and interface name lists.
- `invoke` and `construct` require at least one argument. The parenthesized form they replaced had a spelling for the empty argument list; the unparenthesized form does not, so `onInvokeInstruction` and `onConstructInstruction` parse a mandatory first operand and then call `onOperands`.
- `next` skips a line continuation word, so an instruction may span several lines when every line but the last ends with a reverse solidus. Only the line terminator of the last line terminates the statement. A reverse solidus that is not followed by a line terminator is a lexical error.
- Do not reintroduce a comma or parentheses into instruction operands in the specification, the parser, or the checked-in `.pdl` inputs; the three forms are kept in sync deliberately.

## Runtime And GC

- ReturnInstructionNode has an optional operand: a bare return uses a void constructor argument normalized to NULL, and its visitor skips that NULL. Parser and executable backend already distinguish bare void returns from valued returns; do not require a value in the AST constructor. AST tests construct/collect both forms, and Backend compiles/runs a branching void procedure with explicit bare returns above 255 caller slots.
- PDLC code follows the shared runtime conventions in `AGENTS/CxxSourceCodeStyle.md`: `Arcadia_Thread*` first, status/raise/jump error handling, and precise GC rooting.
- If a new AST, symbol, diagnostic, or compiler object owns references, update its `visit` callback.
