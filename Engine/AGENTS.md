# Engine Folder Guide

## Scope

- `Engine/Engine` is the core engine abstraction library (`${MyProjectName}.Engine`). It owns generic engine state, event queues, backend/backend-context abstractions, node factories, audials abstractions, visuals abstractions, input events, visuals resources, and visuals node interfaces.
- `Engine/UI` is the UI layer (`${MyProjectName}.Engine.UI`). It depends on `Engine` and `Math`, and provides UI events, UI nodes, widget nodes, and concrete UI node types such as canvas and panel.
- `Arcadia.Engine.Application` is a class in core `Engine/Engine` (`${MyProjectName}.Engine`), under `Engine/Engine/Library/Sources/Arcadia/Engine/`. Its configuration and startup/shutdown helpers live there too; it exposes input/window/application event hooks, not a separate module or target.
- `Engine/Audials.Implementation` is the OpenAL-oriented audials backend implementation (`${MyProjectName}.Engine.Audials.Implementation`). It is implementation code, not the core audials API.
- Visuals implementations are not in this folder. The concrete OpenGL4/GLX/WGL/Windows/Linux visuals code lives under `repository/Visuals.Implementation`.
- Before modifying resource classes, resource factories, or backend-context resource management, read `Engine/AGENTS/Resource-Lifecycle-and-Ownership.md`. Follow its lifecycle and ownership rules.


## Build Wiring

- The repository root adds these modules individually with `add_subdirectory(Engine/Text)`, `add_subdirectory(Engine/Engine)`, `add_subdirectory(Engine/UI)`, and `add_subdirectory(Engine/Audials.Implementation)`. There is no `Engine/CMakeLists.txt` aggregator.
- Library products use the repo macros from `CMake/all.cmake`: `BeginProduct`, `OnSourceFile`, `OnHeaderFile`, `OnConfigurationFile`, `OnModuleDependency`, and `EndProduct`.
- When adding a source, header, inlay, or generated configuration file, update the nearest `Library/CMakeLists.txt`; files are registered explicitly.
- Register `.pdl` declarations with `OnSourceFile` alongside their C/header files, including enumerations and native declarations. PDLC discovers module inputs independently, so successful regeneration does not prove that the input appears in the CMake/Visual Studio project.
- The native list binding in Visuals/BackendContext.pdl is declared and called as Arcadia.Engine.Visuals.createVisualsWindowsList. Its generated outputs are Arcadia/Engine/Visuals/createVisualsWindowsList.h and .c.g beneath Library/Sources, and its C name is Arcadia_Engine_Visuals_createVisualsWindowsList. The public Engine aggregate exports its declaration through Visuals/Include.h. Use the qualified PDL name to obtain the proper output namespace; do not keep flat-root copies.
- Core `Arcadia.Engine.Event`, `Arcadia.Engine.Node`, `Arcadia.Engine.NodeFactory`, `Arcadia.Engine.Visuals.Icon`, and `Arcadia.Engine.Visuals.CanvasEvent` register their PDLC `.c.g` through ordinary `OnSourceFile` calls. The shared macro classifies `.c.g` as C. Completed migrations retain ordinary regression tests linked to the real library; temporary Native/Generated providers and snapshots have been retired. Other implementation migrations remain per-class decisions.
- Arcadia.Engine itself uses mapped Engine/Engine.h and Engine.c.g: nine managed fields, collection initialization, visitor and nonvirtual enqueEvent/dequeEvent are PDL-owned. update remains abstract/unbound and there is no public create factory. The module and class both retain the name Arcadia.Engine under separate module/type lookup. getOrCreate is a generated qualified procedure (getOrCreate.h/.c.g) exported through the Engine aggregate; EngineSingleton.c retains only the weak singleton cache, runtime allocation and destruction callback. Do not turn that cache into a strong GC root. Native collection providers remain native.
- Shared opaque native collection declarations live in Runtime/Collections/Library/Sources/Arcadia/Collections/NativeTypes.pdl, owned by Arcadia.Collections. Engine no longer owns those imported types; root configuration and ResourceModels staging include the defining module. Keep dependency includes through Arcadia/Collections/Include.h and do not introduce an Engine dependency into Media's generated VertexDescriptorBuilder.
- CanvasSizeChangedEvent, CanvasDPIChangedEvent and CanvasActivationStateChangedEvent compile generated `.c.g`, covered by the CanvasPayloadEvents case in Tests/WindowCanvasEvents. Preserve the DPI/activation constructor-offset regressions.
- MouseButtonEvent and MousePointerEvent compile generated `.c.g`, covered by the MouseEvents case in Tests/InputEvents. Runtime callbacks accept legacy Integer32 actions and exact typed enums; PDL allocation and superclass forwarding remain strict.
- ApplicationEvent, ApplicationQuitRequestedEvent and the three window events compile generated `.c.g`, covered by the ApplicationWindowEvents case in Tests/WindowCanvasEvents. Nullable windows match their factories and the PDL convention.
- Core Backend/BackendContext, Audials.Backend, Visuals.Backend and DisplayMode compile generated `.c.g`, covered by the BackendBases case in Tests/Backends. Their abstract slots remain unbound.
- Audials.BackendContext and Visuals.BackendContext compile generated `.c.g`, covered by their named cases in Tests/Backends. Audials resource-creation methods are abstract while setMasterVolume retains its no-op default.
- Audials.Node and Visuals.Node compile generated `.c.g`, covered by RenderNodes in Tests/Nodes. Render slots and inherited context setters remain abstract/unbound. EnterPassNode remains an opaque native import.
- Audials.NodeFactory and Visuals.NodeFactory compile generated `.c.g` for their stateless scaffolding, zero-argument constructors/public factories and three/nine bound slots in original order. Their NodeFactoryRuntime.c files retain the native creation algorithms; concrete nodes, DSP algorithms, context locks and resource lifetimes remain native. FactoryNativeNodes.pdl imports only those native product types. Audials/Include.h explicitly exports SoundSourceNode instead of relying on the old factory header's transitive include. Nodes' existing NodeFactory case also runs FactoryFamilies.c: independent ABI/signatures, every override, nullable contexts/results, native real children and definition errors, constructor counts/tags, >255-slot cleanup, collection/finalization and generated wrapper receiver/argument roots. Temporary comparison providers are retired.
- UI.Event, UI.WidgetEvent and the concrete WidgetPositionChangedEvent/WidgetSizeChangedEvent compile generated `.c.g`, covered by UI/Tests/EventBases. The concrete events retain mapped Events/ header paths and exact timestamp/source/two-axis constructor order. WidgetEvent accepts void as a missing source. Preserve the corrected WidgetEvent parent layout and native widget-source liveness regressions.
- UI.Node compiles Node.c.g as a stateless abstract base over Engine.Node, with both inherited context slots unbound and no public factory. Node.pdl also owns the qualified Node.findByName procedure: generated Node/findByName.h/.c.g preserves Arcadia_Engine_UI_Node_findByName through the public UI aggregate. Its declaration now lives in that procedure header rather than the private class header. Search is root-first, depth-first in Container child order, with Natural64 indices and immediate first-match return. Native NodeSearchRuntime.c retains bytewise widget-name comparison, Container boundaries and pointer-presence checks, not traversal. Do not replace presence testing with overridable equality. WidgetNode and actual widget/layout implementations remain native; no cycle-detection or new token/name policy is introduced.
- UI Activatable, HitTestable, Focusable, Scrollable, Renderable and KeyboardInput have verified PDL-owned declarations and implementations. Interface outputs use ordinary .c/.h paths. The normal CLI reproduces all twelve files byte-for-byte against their prior C baseline, so no replacement provider or source-extension switch is required. EventBases/Interfaces.c checks all nine operations and real ButtonNode/ScrollPanelNode consumers.
- UI.populateContainerFromDefinition is a qualified generated procedure from DefinitionFactory.pdl. DefinitionFactory.h re-exports its generated header with the original C signature, while DefinitionFactory.c keeps native createNodeFromDefinition dispatch and small ADL/collection/Container boundaries. Preserve the captured child list/count, current-element reads, resolution/construction/add ordering, duplicates, nested factory calls and partial progress on errors. Do not snapshot, pre-resolve, deduplicate or roll back. EventBases/Populate.c retains ABI, real nested StackPanel construction, list growth/replacement, empty-source unused targets, failure/deep-stack and generated input/list/child GC-root regressions. This is setup traversal; pixel/sample loops remain separate performance-sensitive work.
- PointerInput, Container and ValueControl are also verified ordinary PDL interface output; their six source/header files regenerate byte-identically. The existing EventBases/Interfaces.c now covers all nine capability interfaces and seventeen operations, including Natural64 counts/indices, erased child pointers and by-value Arcadia.Value payloads. Native ButtonNode, ScrollPanelNode and ToggleNode remain the real implementation consumers; no new CTest registrations are added.
- Scene compiles generated Scene.c.g with the original three managed fields and six bound no-op defaults. It has no public factory. Engine and SceneManager are generated; Signal remains a native import. The qualified createSceneQuitRequestSignal binding uses SceneRuntime.c only for required-dependency/null checks and native Signal creation; do not silently broaden the constructor's non-null Engine/SceneManager contract. Nodes' Scene case covers ABI, constructor errors, native subclasses, all defaults/overrides, managed lifetime and Signal usage. Temporary comparison providers are retired.
- SceneManager compiles SceneManager.c.g: three managed fields, constructor, visitor and nonvirtual getScene/setScene are PDL-owned. Native SceneManagerRuntime.c provides required Engine validation/Signal creation, literal pointer comparison (not overridable equality or identity), and exception-safe Signal argument-frame handling. Publish the new scene before emission; same-pointer assignments emit nothing, nested transitions persist, and notification failure does not roll back the state. Preserve nullable old/new payloads and their roots through callbacks. Temporary comparison providers are retired.
- Core Arcadia.Engine.Application compiles Application.c.g: quitRequested plus four managed references, singleton Engine acquisition, a fresh window list, and nonvirtual quit/directory property methods. All five original slots remain abstract/unbound in their original order; no public create factory is added. The three historically slot-only event operations also have conventional generated typed wrappers, with no additional slots. ApplicationRuntime.c retains only the null/empty string check behind the qualified requireConfigurationDirectoryName binding. Preserve ArgumentValueInvalid and do not introduce path restrictions or normalization. DDL.Node is an opaque import through DDL's master header.
- DisplayDevice compiles generated `.c.g` as a stateless abstract base, preserving getCurrentDisplayMode/getAvailableDisplayModes/getBounds/getName/getId slot order. Its Backends case checks direct C output pointers, typed/nullable returns, native overrides, exceptions and receiver/managed-payload lifetime without activating a display.
- SoundSourceResource and StreamingSoundSourceResource compile generated `.c.g` at their mapped Audials/Resources paths while retaining .Implementation in runtime/C type names. Their native audials Resource parent has a declaration-only constructor signature; ownership/refcount/context behavior remains native. Preserve abstract slot order and the streaming arity regression: validate count before reading/forwarding argument 1.
- AudioStreamProvider compiles generated `.c.g` at the mapped Audials/Providers path. sampleRate is Natural32, getSampleRate remains nonvirtual and read forwards a native managed Media.DSP.Buffer plus an output Size pointer. Buffer.pdl imports the existing Media object/header without regenerating its storage implementation. DSPStreamProvider remains native, includes the Media master explicitly and uses a base-type cast for inherited sampleRate.
- ConstantBufferResource, FrameBufferResource and TextureResource compile generated `.c.g` at their existing paths, covered by ThinResources in Tests/VisualResources, including the V-setter regression. They remain stateless over native Resource; its PDL constructor signature does not change its native ownership behavior.
- ProgramResource compiles generated `.c.g`, also covered by ThinResources in Tests/VisualResources. It adds no state/slots and forwards construction to native Resource. Inherited base slots remain unbound for native backends to override.
- MaterialResource compiles generated `.c.g` with four scalar fields and a five-argument constructor (context, blend enabled, source/destination blend functions, ColorSource). Its inherited Resource operations remain unbound. OpenGL4 forwards those five arguments while retaining its texture/program fields and existing acquisition rollback/load/unload/unlink protocol. The MaterialResource case in VisualResources verifies the scalar base, native subclasses, argument/enum errors, deep stacks and GC/finalization; no extra permanent comparison targets remain.
- `Configure.h` files are generated from checked-in `Configure.h.i` templates via `OnConfigurationFile`. Include the generated `Configure.h` through the module's normal public/private include path, not by hard-coding the binary tree.
- `Engine/Audials.Implementation` is option-gated by `${MyProjectName}.Engine.Audials.Implementation.OpenAL.Enabled`. Do not assume OpenAL headers or libraries are available unless that option is enabled.
- `${MyProjectName}.Engine` registers an asset directory via `OnAssetsDirectory` in `Engine/Engine/Library/CMakeLists.txt`; its contents are provided to executables that link the library. See `## Assets`.

## Assets

- `${MyProjectName}.Engine` owns the source asset directory `Engine/Engine/Library/Assets`, registered in `Engine/Engine/Library/CMakeLists.txt`. Shared CSS color definitions live at `Engine/Engine/Library/Assets/Colors/CSS/` and are staged at runtime path `Assets/Colors/CSS/` (one `.adl` per CSS color keyword, defining `Colors.<CamelCaseName>`).
- The engine provides these assets to executables it is linked to. `EndProduct` in `CMake/all.cmake` stamps `ARCADIA_ASSETS_DIRECTORIES`/`ARCADIA_ASSETS_FILES` target properties from the `OnAssetsDirectory` input; `CopyProductAssets` uses `Arcadia_collectTargetAssets` to walk the target's link closure (`LINK_LIBRARIES` and `INTERFACE_LINK_LIBRARIES`, including `$<LINK_ONLY:...>` forms, deduplicating visited targets) and copies every collected asset into the executable's binary tree, preserving relative paths.
- A consumer only needs to link the engine library directly or transitively (e.g. via `${MyProjectName}.Engine.UI`); no per-consumer copy of `Assets/Colors/CSS` is required. Consumers load the assets at runtime with paths relative to the working directory, e.g. `Assets/Colors/CSS/Red.adl`.
- Adding or removing engine-owned asset files requires no CMake edit (`OnAssetsDirectory` globs the tree at configure time).

## Include Boundaries

- Generated code follows the same boundary: a type dependency from another PDL module must use that defining module's master include, not its individual type header. Native header mappings describe local interoperability; they do not authorize bypassing another module's public aggregate or defining its private include switch.
- Public consumers of the core engine should include `Arcadia/Engine/Include.h`, not individual core headers. Many core headers intentionally reject direct inclusion unless `ARCADIA_ENGINE_PRIVATE` is set by the aggregate include.
- Public consumers of UI should include `Arcadia/Engine/UI/Include.h`.
- Public consumers of `Arcadia.Engine.Application` and its helpers should include `Arcadia/Engine/Include.h`.
- Public consumers of Audials implementation registration should include `Arcadia/Audials/Implementation/Include.h`.
- Keep aggregate include files in sync when adding public types.

## Runtime Patterns

- Follow the shared C/C++ source code style guide in `AGENTS/CxxSourceCodeStyle.md`, including object/type patterns, `Arcadia_Thread*` calling conventions, error handling, and GC/rooting rules.
- Backend objects represent available systems; backend contexts are heavyweight active resources such as audio or video contexts. Avoid creating contexts implicitly unless nearby code already does so.
- Engine registration APIs store backend and node-factory type objects in `Arcadia_Set` instances. Register derived type objects, not instances.

## PDL Declarations

- Several event and enum-like declarations have `.pdl` inputs beside C and header files. Generated-looking `.c`/`.h` files coexist with these inputs.
- Follow the generated-source guidance in `AGENTS/CxxSourceCodeStyle.md` before editing generated-looking output.
- The nine core visuals resource `.pdl` files model all 41 public resource functions, fields, ownership, constants and value-record aggregates in PDL terms. `readonly reference Arcadia.Void` models byte inputs, readonly Math inputs are object views, and `output reference Arcadia.Integer32` models FrameBufferResource.getSize's results. Resource.ref/unref are nonvirtual; FrameBufferResource.setSize is virtual. No explicit inherited base fields or C dispatch declarations belong in PDL. The C backend verifies the models against native headers; native implementations retain their ownership/GC behavior.
- Material creation APIs and backend material state use the shared compiler-owned Arcadia.Engine.Visuals.ColorSource enum. The old MaterialResource-specific enum has been removed without compatibility aliases. The eight derived resource headers remain under `Visuals/Resources`, although runtime names omit `.Resources`; explicit header mappings preserve that distinction. ADL's separate asset-language enum retains its TextureVertex variant and is translated by MaterialNode.
- KeyboardKey remains a plain native enum. Its PDL declaration imports KeyboardKey.h without duplicating the key set; KeyboardKey.i owns the macro-expanded values, aliases and descriptions, and KeyboardKey.c owns the native implementation/toString behavior. Preserve that macro pipeline and do not enable declaration regeneration for this enum during event migrations.
- KeyboardKeyEvent uses generated production code, preserving key/action field order, factory arguments and nonvirtual getters, with the KeyboardEvent case in Tests/InputEvents.
- ColorSource is a compiler-owned enumeration defined in Visuals/ColorSource.pdl, with Mesh=0, Vertex=1 and Texture=2. Normal PDLC generation owns the existing ColorSource.h and ColorSource.c (enum sources use .c, not .c.g). Its generated implementation is byte-identical to the former native body; C names, descriptor and ABI remain unchanged. VisualResources has a ColorSource case covering constants, signature/size, runtime name/kind, registration and boxed values through GC.
- UI StackPanelNodeAlignment is compiler-owned by Nodes/StackPanelNodeAlignment.pdl. Its generated-enum mapping preserves the Nodes/ header/source paths and original path-derived guard while retaining Arcadia.Engine.UI.StackPanelNodeAlignment and all C names. Start=0, Center=1, End=2, Stretch=3. The native and generated implementations pass the same EventBases/Alignment.c ABI/descriptor/GC boxing and real StackPanelNode setter/child-override regressions, including invalid-value rejection without mutation. Generated .c changes only formatting; StackPanelNode, layout and unmanaged slot storage remain native. No per-enum CTest target or comparison provider is retained.
- Resource, EnterPassResource, ModelResource and VertexBufferResource still use `native implementation` for header generation and retain native C bodies. The other five resource bases use generated-class mappings at their existing headers/.c.g paths. MaterialResource uses ColorSource from the public Engine aggregate and owns no associated enum. Window remains plain native. Native consumers must include their own dependencies, such as Math.
- Resource header/model verification is not executable ownership verification. Resource.context remains a non-owning backend reference; establish borrowed-reference execution semantics and ref/unref overflow/underflow/cleanup before replacing Resource or derived native bodies. EnterPassResource's native constructor roots its receiver, both matrices and clear color across createConstantBufferResource: until LeaveConstructor publishes the derived type, Resource's visitor cannot retain those fields, and native allocation does not root the receiver. Pop temporary roots on success/error and publish viewerConstantBuffer only after Resource_ref succeeds. VisualsBackendContext's construction probe forces callback GC, checks weak receiver/field observers, callback/refcount-overflow failures and deep-stack cleanup; fixture callbacks no longer suppress collection. Tests still release the viewer-buffer dependency before final collection to honor the concrete backend unlink protocol. Keep this native correctness repair separate from resource migration/borrowed-reference semantics.
- Visuals.BackendContext compiles generated code, covered by Backends. ResourceModels checks all nine resource models, including five generated bases: 41 public functions, 27 fields, six record members, 39 virtual slots and two nonvirtual methods. Model previews accept native/generated classes; its field-count guard must reflect intentional declaration changes before contracts can be regenerated.
- Audials.BackendContext references generated AudioStreamProvider/SoundSourceResource/StreamingSoundSourceResource declarations. SampleBuffer remains a native import through Media's master, and audials Resource retains its native header/body. Preserve the historical .Implementation names on resource types and existing Audials/Providers or Audials/Resources file mappings.
- Native ModelResource temporarily roots its receiver/localToWorldMatrix across the constant-buffer callback and dependency acquisition/rollback while Resource's active visitor cannot trace derived state. Preserve original argument values when pushing roots and release roots on success/failure. VisualResources' ModelConstruction collects in that callback and checks weak liveness/release, every acquisition overflow, aliased rollback, callback failure and >300-slot cleanup. Resource.context remains borrowed, dependency counts/order stay native and unchanged; this is not a PDL migration or GPU-retirement proof.
- Resource API dependencies include native Media PixelBuffer/VertexDescriptor declarations and native Math Color4Real32/Matrix4Real32 declarations. They map to their public aggregate headers, preserving module-private include boundaries and Math's template-generated definitions. The root `Modules.pdl` includes `repository/Math` for these dependencies.
- Media.VertexDescriptor now uses a complete native-implementation declaration model at its existing header: stride, ImmutableList pointer, Natural32 vertexSize and three nonvirtual getters. Its private factory remains only in VertexDescriptor.module.h; native constructor/visitor/calculation bodies remain unchanged apart from explicit dependency includes. The generated base member is `_parent`; repository consumers do not access the old `parent` spelling. Geometry/VertexBuilder.c verifies ABI/getters, full-width stride, legacy runtime List transport, Natural32 wrapping and native descriptor/list/element GC. No executable descriptor or Collections implementation migration is implied.

## Verification

- Completed migrations retain ordinary linked-library cases in seven suites: CoreEvents (Event, CanvasEvent), InputEvents (MouseEvents, KeyboardEvent), WindowCanvasEvents (CanvasPayloadEvents, ApplicationWindowEvents), Nodes (Node, NodeFactory, RenderNodes, Engine, Scene, Application, SceneManager), Backends (BackendBases, AudialsBackendContext, VisualsBackendContext, DisplayDevice, SoundSourceResource, StreamingSoundSourceResource, AudioStreamProvider), VisualResources (Icon, ColorSource, MaterialResource, ThinResources, plus the native ResourceLifecycle regression), and the separate UI/Tests/EventBases. AudialsStreaming and Engine.Text remain independent. Temporary comparison providers/snapshots are retired.
- Each core case lives in its own named C file and retains its safeExecute/process boundary. The Engine-independent Arcadia.Testing library in Runtime/Testing dispatches named cases, reports the component on failure and runs remaining cases after an ordinary failure. No selector runs the entire suite; `--case NAME` runs only that component, including VisualResources' ColorSource enum regression. Unknown/malformed selections fail. CTest discovers `Executable.Case` registrations through `--list`, without an additional whole-suite workload. Read `AGENTS/Testing.md` for shared rules.
- UI/Tests/EventBases also exposes `EventHierarchy`, `Alignment`, `Node`, `Populate`, and `Interfaces` in its original top-level order. Each existing safeExecute boundary and grouped regression helper is retained; the former `EventBases` whole-suite selector is retired. Engine.Text/MarkupTests separately exposes `ParseRuns`, `RejectUnknownAttribute`, and `RunModels`; preserve its inverted result for the unknown-attribute negative case. Case discovery introduces no production dependency or additional executable.

- An intermittent Nodes failure remains unexplained: repeated direct/case/full-suite passes do not prove a fix or establish a compiler/runtime cause. Capture the failing case/output and reproduction context before attributing it to a migration.

### PDLC Implementation Migration Workflow

Nodes' SceneManager case (--case SceneManager) covers three-field/no-own-slot ABI and exact signatures, native manager/scene descendants, fresh Signals, pointer identity with overridden equality/identity, null/same/different transitions, callback-visible publication, reentrant transitions, failure-without-rollback and deep-stack cleanup. GC coverage isolates all three fields, old/new notification payloads, cycle finalization and otherwise unrooted receiver/arguments. Constructor wrong types/null and counts 0..255 except 1 retain exact errors; production wrappers reject null/wrong receivers and wrong scene types without mutation. Signal callbacks leave the caller-owned frame untouched.

1. Audit the actual native constructor, fields, dispatch initialization, callbacks, GC/ownership, and failure behavior against the PDL model. Preserve original declaration documentation in PDL before replacing headers. Empty ordinary PDL bodies are implementations, not abstract declarations: native unbound base slots such as Node's setters require `method abstract`.
2. Preserve a native reference under the owning test's source directory. Verify its contents against the corrected native implementation (Git hashes can establish an unchanged snapshot). If the audit exposes a native bug, reproduce it with the test and record the correction; generated/native agreement alone cannot prove a shared bug absent.
3. Run the same meaningful assertions in Native and Generated variants before switching. Native compiles the test-owned reference directly; Generated supplies the actual `.c.g` candidate. Link Engine's real consumers/types where practical. Cover constructor arity and every value tag, boundary values, superclass chains, dispatch, GC/lifetime, and failure stack cleanup relevant to that class. Use distinct axis values and both Boolean states to detect argument swaps and the canvas offset regressions.
4. Only after the pair passes, register the production `.c.g` with plain `OnSourceFile`; the shared macro recognizes it as C. Remove the old production `.c`, retaining its reference only in tests. Do not disguise it as `HEADER_FILE_ONLY`, repeat local language overrides at these registrations, or publish copied headers.
5. Run a Production variant with no replacement implementation source: it must resolve the class from the actual Engine library. Rebuild affected native/derived consumers (typically UI, visuals implementation, and Anima). Inspect generated project compile entries when source ownership is in doubt; an IDE listing is not proof that a file is compiled.
6. Regenerate through the normal CLI again and verify byte-identical output. Record which tests/builds ran and their scope; an application build does not establish an interactive smoke run. Complete only the verified class/family migration, not the broader source-adoption task.
7. After the migration gates pass, retire temporary Native/Generated targets, snapshots and provider wrappers. Retain the Production assertions as an ordinary named case in the appropriate linked-library suite, with its own safeExecute boundary. Preserve all safety/GC checks. Keep compiler fresh-generation/ABI/module-boundary tests separate; do not accumulate permanent triples or a permanent executable per migrated class.

During an active migration, Native/Generated variants supply the class's public symbols in the test executable, so the corresponding object is not extracted from the static Engine archive. Keep temporary providers in separate translation units; Production intentionally has no provider. Once retired, the unsuffixed regression test must continue resolving the real library implementation.
